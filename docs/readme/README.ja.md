**HTML PGP** は、GnuPG に付属する証明書マネージャー [Kleopatra](https://apps.kde.org/kleopatra/) の考え方を受け継いだ、OpenPGP の鍵管理・暗号化ツールです。しかも、単独の HTML ファイル 1 つに収まっています。自分の鍵ペアと他の人の公開鍵を保管するキーリングを持ち、新しい鍵（RSA、Curve25519、NIST 曲線と Brainpool 曲線、OpenPGP v6 の Ed25519 と Ed448）を作成し、鍵を認証し、テキストやファイルの暗号化、署名、復号、検証を行います。

GnuPG や Kleopatra と同じ OpenPGP を話します。鍵、メッセージ、署名は双方向にやり取りでき、テストも GnuPG 自体を相手に確認しています。

すべてオフラインで動作します。アカウントもサーバーもネットワークリクエストもありません。ページにはネットワークアクセスが一切ありません。鍵はブラウザーに保存され、秘密鍵はパスフレーズで暗号化されたままで、パスフレーズ自体は保存されません。同じページを、アプリとしてインストールできる [PWA](#github-pages) として、またタブの横で開く [Chrome 拡張機能](#chrome-拡張機能)としても使えます。

## 使い方

`build/html-pgp.html` をビルドし（「[ビルド](#ビルド)」を参照）、ブラウザーで開きます。ディスクから直接開いても問題ありません。GitHub Pages の PWA や拡張機能を使うこともできます。

アプリには Kleopatra と同様に 3 つのビュー、「鍵」「メモ帳」「ファイル」と、「設定」があります。

### 鍵

- **新しい鍵ペア** — 名前とメールアドレス、そして秘密鍵を保護するパスフレーズを入力します。「アルゴリズムと有効期間」では、アルゴリズム（「[アルゴリズム](#アルゴリズム)」を参照）と鍵の有効期間を選びます。有効期間は、GnuPG や Kleopatra が作る鍵と同じく、既定で 3 年です。鍵を作成すると、すぐにバックアップを勧められます。キーリングはこのブラウザーの中にしかないからです。
- **インポート** — ファイル（`.asc`、`.gpg`、`.key` など。1 つのファイルに 1 つまたは複数の鍵を含められ、テキスト形式でもバイナリ形式でも可）、クリップボード、または貼り付けたテキストから取り込みます。鍵ビューにドロップしたファイルもインポートされます。すでにキーリングにある鍵はマージされます。新しいユーザー ID、サブ鍵、署名が追加され、秘密鍵は対応する公開鍵に結び付けられます。GnuPG の失効証明書（`.rev`）は、確認したあとにのみインポートされます。鍵が永久に失効するためです。
- **エクスポート** — 選択した公開鍵を、テキスト（`.asc`）またはバイナリ（`.gpg`）で、ファイルまたはクリップボードに書き出します。⌘/Ctrl や Shift を使って複数の鍵を選択できます。
- 一覧には、各鍵の名前、アドレス、有効性、有効期限、鍵 ID が表示されます。検索では名前、アドレス、鍵 ID、フィンガープリントで鍵を探せ、フィルターでは自分の鍵ペア、認証済みの鍵、誰も認証していない鍵、期限切れや失効した鍵だけを表示できます。

鍵の詳細には、GnuPG の表示と同じ 4 文字ずつのグループに区切ったフィンガープリント、ユーザー ID とその認証者、主鍵とサブ鍵（アルゴリズム、用途、日付つき）、そしてテキスト形式の公開鍵が表示されます。自分の鍵の場合は、⋯ メニューにさらに次の項目があります。

- **有効期限を変更** — 鍵とそのサブ鍵の新しい日付を設定します。期限なしにもできます。変更後は公開鍵をもう一度共有して、他の人に反映させてください。
- **ユーザー ID を追加** — 同じ鍵に別の名前やアドレスを加えます。主ユーザー ID は主のままです。
- **パスフレーズを変更** — 現在のパスフレーズが記憶されている間でも、まず現在のものを尋ねられます。空にすると、警告のあと鍵は無保護になります。
- **秘密鍵をバックアップ** — 秘密鍵をパスフレーズで保護されたまま、`Name_0xKEYID_SECRET.asc` として保存します。最初にパスフレーズを尋ねるので、バックアップが開けることを確認できます。
- **失効証明書** — 鍵と一緒に作られたもので、鍵とは別に保管してください。鍵を紛失したり盗まれたりしたら、この証明書をインポートし、失効した鍵を共有します。
- **鍵を失効**、および複数あるユーザー ID のうち 1 つの**失効**。

### 認証

鍵を認証するとは、「この鍵がこの人のものであることを確認した」と表明することです。まず所有者とフィンガープリントを確認します。直接会うか、声を知っている相手との通話で確認してください。そのうえで、鍵の詳細で**認証**を押し、ユーザー ID を選びます。認証は GnuPG と同じようにあなたの鍵の主鍵で行われ、GnuPG にも受け入れられます。

有効性は、Kleopatra による信頼の輪のもっとも単純な解釈に従います。自分の鍵は完全に信頼され、自分が認証した鍵は**認証済み**になります。それ以外の鍵も使えますが、使われる場所すべて（一覧、受信者の中、その鍵が作った署名）で**未認証**と表示されます。

### メモ帳

メッセージを入力し、**受信者**を選びます（入力に応じて名前、アドレス、鍵 ID で見つかります）。そして**暗号化**を押します。「署名者」で鍵を選んでいる場合は**署名して暗号化**を押します。「自分宛てにも暗号化」を使うと自分の鍵が加わるので、送ったものを自分でも読めます。「パスワードで暗号化」を使うと、誰でも復号できるパスワードが、受信者に加えて、または受信者の代わりに追加されます。**署名のみ**は、クリア署名付きのテキストを作ります。読める状態のまま、下に署名が付きます。

暗号化または署名されたメッセージを貼り付けて**復号 / 検証**を押します。テキストはその場で復号され（必要なときは鍵のパスフレーズが尋ねられます）、付いているすべての署名が検査されます。結果は、正しい、不正（テキストが変更されている）、またはキーリングにない鍵による署名のいずれかです。「元のテキストを表示」で元に戻せます。⌘/Ctrl+Enter でメッセージの復号、またはプレーンテキストの暗号化ができます。貼り付けた鍵は、インポートするよう提案されます。

### ファイル

ボタンでファイルを追加するか、ウィンドウにドロップします。各ファイルは種類を判別するために調べられます。通常のファイル、暗号化されたもの、署名されたもの、分離署名、鍵、失効証明書のどれかです。

- **署名 / 暗号化** — 通常のファイル向けです。自分の鍵のどれかで署名する、自分宛て、他の人宛て、パスワードで暗号化する、またはそれらを組み合わせます。暗号化されたファイルには `.gpg`（テキストなら `.asc`）が付きます。署名のみの場合は、各ファイルの横に分離署名 `.sig`（または `.asc`）が作られます。
- **復号 / 検証** — それ以外のファイル向けです。分離署名は、署名対象のファイルを名前で探します（`report.pdf.sig` は `report.pdf` に対応）。見つからなければ尋ねられます。復号されたファイルは、暗号化されたファイルの名前から `.gpg` を除いた名前になります。
- **鍵をインポート** — ここにドロップされた鍵ファイル向けです。

各結果は、それぞれのボタンで、またはまとめて保存できます。

### パスフレーズ

一度ロック解除した秘密鍵は、gpg-agent と同じように、しばらくロック解除されたままになります。既定は 10 分で、設定で「毎回尋ねる」から 4 時間まで選べます。保持されるのは復号された鍵だけで、ページのメモリー内にのみあります。パスフレーズは保持されず、ディスクにも書き込まれません。メニューの「パスフレーズを消去」ですべて一度にロックされます。ページを再読み込みしても同様です。

### スマートフォンで

ページはスマートフォンでも動作します。画面は一度に 1 つ、ビューは下部のタブバーにあり、鍵の詳細は戻るボタン付きの専用画面に表示され（システムの戻るジェスチャーも使えます）、メニューは下から現れます。iOS では、保存したファイルは共有シートに渡され、そこに「ファイルに保存」があります。

## アルゴリズム

| 選択肢 | GnuPG での名称 | 備考 |
| --- | --- | --- |
| ECC Curve25519 | ed25519 + cv25519 | GnuPG や Kleopatra と同じ既定値。短く、高速で、どこでも読めます。 |
| ECC NIST P-256、P-384、P-521 | nistp256, nistp384, nistp521 | ECDSA と ECDH。 |
| ECC Brainpool P-256、P-384、P-512 | brainpoolP256r1… | ECDSA と ECDH。ドイツやヨーロッパでよく使われます。 |
| RSA 2048、3072、4096 | rsa2048… | 最も古く、最も広く読めます。作成に数秒かかります。 |
| Ed25519 + X25519 (OpenPGP v6) | ed25519 + x25519 | RFC 9580 の鍵。**GnuPG と Kleopatra はまだ読めません。** |
| Ed448 + X448 (OpenPGP v6) | ed448 + x448 | RFC 9580 の鍵。上と同じです。 |

どの鍵も、GnuPG の作り方と同じく、認証と署名を行う主鍵と、暗号化を行うサブ鍵で構成されます。ほかのアルゴリズムの鍵（たとえば古い GnuPG のキーリングにある DSA や ElGamal）も読み込んで使えます。ただし、新しく作ることはありません。secp256k1 は除外しています。openpgp.js は、別途指定しない限りこれを拒否するためです。

## GnuPG と Kleopatra との互換性

`tests/gnupg.mjs` は、使い捨てのホームディレクトリで GnuPG 自体を実行し、アプリが書き出したものを検査します。`tests/pgp.mjs` は、GnuPG が書いたもの（`tests/fixtures/gnupg/`。`tools/gnupg-fixtures.sh` で一度だけ作成）を読み込みます。両方向で確認しています。

- ここで作成した v4 のすべてのアルゴリズムの鍵は、用途も含めて GnuPG にインポートされ、使えます。GnuPG は私たちのメッセージを復号し、署名を検証でき、私たちも GnuPG がそれらの鍵宛てに暗号化したものを復号できます。
- GnuPG は、私たちが設定した新しい有効期限、追加および失効したユーザー ID、他の鍵への認証、失効証明書を認識します。
- GnuPG の鍵、メッセージ（OCB で暗号化されたものを含む）、クリア署名付きテキスト、分離署名、パスワードで暗号化されたメッセージ、失効証明書は、ここで読み込めます。

Kleopatra から鍵を移すには、自分の鍵ペアを選択して Export secret keys（または “Backup secret keys”）を実行し、そのファイルをここにインポートします。他の人の公開鍵も同様に Export で書き出します。逆に、ここから Kleopatra へは、公開鍵をエクスポートするか秘密鍵をバックアップして、そのファイルを Kleopatra にインポートします。

## Chrome 拡張機能

同じアプリを Chrome のサイドパネルで、読んでいるページの横に表示します。ツールバーのボタンで開きます。任意のページ（ウェブメール、フォーラム、テキストフィールドなど）で暗号化または署名されたテキストを選択し、コンテキストメニューの**HTML PGP で復号 / 検証**を選ぶと、パネルのメモ帳で復号と検証が済んだ状態で開きます。**HTML PGP で暗号化**は、選択したテキストを渡すので、受信者を選べます。

拡張機能は、必要最小限の権限しか求めません。サイドパネル、コンテキストメニュー、独自のストレージ、そしてクリックしたタブ（activeTab）です。activeTab は、コンテキストメニュー自体では失われてしまう改行を保ったまま選択範囲を読み取るために使います。それ以外では、どのウェブサイトにもアクセスできず、拡張機能のページも、アプリと同様にネットワークアクセスがありません。ページを読み取れない場所（Chrome 自体のページ、ウェブストア、PDF）では、メニューが持つ選択範囲のコピーを使い、その armor を行ごとに元の形へ戻します。

拡張機能は独自のキーリングを持ちます。ブラウザーはオリジンごとにデータを分けて保存するため、単独ファイル、PWA、拡張機能にはそれぞれ別のキーリングがあります。鍵を移すには、エクスポートとインポート、またはバックアップを使います。

`npm run build` でビルドし、`build/extension/` を `chrome://extensions` で読み込みます（デベロッパー モード → パッケージ化されていない拡張機能を読み込む）。Chrome ウェブストア向けには `build/html-pgp-extension-<version>.zip` を使います。

## セキュリティ

- **ページの外には何も出ません。** ページの Content-Security-Policy は `connect-src 'none'` と `default-src 'none'` を指定しています。fetch は使えず、外部の画像やフォントもなく、外へ送信するフォームもありません。スタイル、openpgp.js、アイコンなど、すべてがインライン化されています。ビルドは外部の `src` や `href` があると失敗し、CI でもビルド済みのファイルを再度検査します。PWA 版は、独自のマニフェスト、サービスワーカー、アイコンを読み込めます。拡張機能のページには、マニフェストで同じポリシーが設定されています。
- **秘密鍵は暗号化して保存されます。** キーリングはブラウザーの IndexedDB にあり、鍵ごとに 1 レコード、openpgp.js が出力する armor 形式で保存されます。秘密鍵はパスフレーズで暗号化されたままで（AES-256。鍵はパスフレーズから、GnuPG と同じく反復とソルト付きの S2K で導出されます）、必要なときだけメモリー内で復号されます。パスフレーズは保存されません。パスフレーズのない鍵は、その詳細に明記されます。
- **ロック解除された鍵は消去されます。** 設定した時間が過ぎたとき、「パスフレーズを消去」を押したとき、ページを閉じたときです。
- **パスフレーズ欄はあえてテキスト入力にしています。** 文字を透明にし、その上にドットを描いています。macOS では、パスワード欄が Secure Input を有効にし、ラテン文字のキーボード配列を強制します。そのため、キリル文字、ギリシャ文字、アラビア文字のパスフレーズは入力できなくなってしまいます。この欄はブラウザーにそのようなヒントを与えず、それでも入力内容は隠し、コピーもできません。
- **署名は、信頼する鍵によって判断されます。** 誰も認証していない鍵による正しい署名は、そのことを示し、フィンガープリントを確認すべき理由も伝えます。
- **ブラウザーが信頼の基盤です。** このページでコードを実行できるもの、またはブラウザーのプロファイルを読めるもの（すべてのサイトにアクセスできる悪意ある拡張機能、コンピューター上のマルウェア）は、ページが読めるものをすべて読めます。秘密鍵のバックアップは別の場所に保管してください。ブラウザーのデータを消去すると、キーリングも削除されます。

## 機能

- IndexedDB のキーリング。このオリジンのアプリのウィンドウ間で共有され、1 つのウィンドウでの変更はほかのウィンドウにも反映されます。
- 12 種類の新しい鍵ペア。有効期限を設定でき、失効証明書も一緒に作られます。
- テキスト形式とバイナリ形式の鍵のインポート。複数同時に可能で、既存のものとマージされます。GnuPG の失効証明書は確認のうえで取り込みます。
- 公開鍵のエクスポート、秘密鍵のバックアップ。1 つでもすべてでも可能です。
- 他の人の鍵の認証。有効性は自分の認証から決まります。
- 自分の鍵の変更（有効期限、ユーザー ID、パスフレーズ、失効）。GnuPG と同様に署名を追加する形で行うので、鍵はどこでも読め、他の人による認証も保たれます。
- メモ帳: 暗号化、署名、署名して暗号化、パスワードで暗号化、復号、検証。
- ファイル: ファイルにも同じ操作、分離署名、複数ファイルの同時処理。
- パスフレーズをしばらく記憶（メモリー内のみ）。
- ライトテーマとダークテーマ。システムに合わせるか、選択できます。
- 17 言語。アラビア語とウルドゥー語は右から左へ表示します。
- スマートフォン向けレイアウト。PWA はスマートフォンでもコンピューターでもインストールでき、オフラインで動作します。
- Finder やエクスプローラーからインストール済みの PWA で開いたファイルは、そのファイルビューに入ります。
- 選択したテキスト用のコンテキストメニューを備えた Chrome 拡張機能。

## 翻訳

インターフェースは英語に加えて 16 言語に対応しています。中国語、ヒンディー語、スペイン語、フランス語、アラビア語、ベンガル語、ポルトガル語、ロシア語、ウルドゥー語、インドネシア語、ドイツ語、日本語、マラーティー語、テルグ語、トルコ語、ウクライナ語です。設定で選ばない限り、ブラウザーの言語に従います。アラビア語とウルドゥー語は右から左へ表示されます。

英語のテキストはコード内にあります。`t('context', 'English text')`、数を含むテキストなら `tn('context', '{count} key', '{count} keys', n)` で、通常の文字列リテラルを使います。`tools/i18n.mjs` が正規表現でそれらを見つけます。テンプレートでは、`data-i18n` が要素のテキストを、`data-i18n-attr` が title、placeholder、aria-label を翻訳します。各言語は辞書 `src/locales/<code>.json` で、`{ "context": { "English text": "translation" } }` の形式です。複数形は `Intl.PluralRules` で扱います。辞書にない文字列は英語で表示されます。

`npm run i18n` は、言語ごとに、辞書に足りない文字列と、辞書にはあるのにインターフェースでもう使われていない文字列を出力します。`npm test` は辞書を検査します。古いキーがないこと、プレースホルダーが同じであること、すべての複数形があること、各 context が一度だけ現れることです。Chrome が拡張機能自体について表示するもの（名前、説明、ボタンのタイトル）は、同じ辞書の context `manifest` から取られます。

## ビルド

```sh
npm install
npm run build          # build/html-pgp.html, build/pages/, build/extension/ とその zip
npm run watch          # 変更のたびに再ビルド
./build.sh             # 同じ内容。初回は依存関係もインストール
```

`build.mjs` は、esbuild で `src/app/main.ts` を 1 つのスクリプトにまとめ、それとスタイル、アイコンを `src/app/template.html` にインライン化します。実行時の依存関係は openpgp.js だけです。

```sh
npm run check          # 以下をすべて順に実行
npm run typecheck      # tsc --noEmit
npm test               # Node での単体テスト。tests/gnupg.mjs には gpg が必要で、なければその旨を表示
npm run test:browser   # ヘッドレス Chrome でページ、PWA、拡張機能をテスト
npm run shots -- DIR   # 主要な画面すべてのスクリーンショットを DIR に保存
npm run icons          # PNG アイコン。assets/*.svg から描画
```

ブラウザーテストは、DevTools プロトコルでローカルの Chrome を操作し、Node 以外の依存関係はありません。`CHROME=/path/to/chrome` で使う Chrome を指定できます。

## バージョンとリリース

バージョンは `package.json` だけに書かれています。`v<version>` のタグが付いたコミットのビルドはそのまま表示します。それ以外のビルドにはコミットが付きます（`0.1.0+1a2b3c4`）。そのため、`main` からビルドしたページがリリースと間違われることはありません。リリースするには `npm version minor && git push --follow-tags` を実行します。リリースのワークフローは、タグが `package.json` と一致することを確認し、テストを実行して、`html-pgp-<tag>.html`、`html-pgp-extension-<tag>.zip`、`SHA256SUMS.txt` を添付します。

## GitHub Pages

`build/pages/` は、同じページをインストール可能な PWA にしたものです。マニフェスト、アイコン、そして一度開けばオフラインでも動作し続けるサービスワーカーが含まれます。`.github/workflows/pages.yml` が `main` へのプッシュごとにこれをビルドしてテストし、GitHub Pages にデプロイします（Settings → Pages → Source: GitHub Actions）。デプロイ後は `https://<owner>.github.io/html-pgp/` で公開されます。

このページも、やはりどこにも接続しません。ポリシーが許可するのは、自身のマニフェスト、ワーカー、アイコンだけです。新しいデプロイは、実行中のバージョンの横にインストールされて待機します。設定には「バージョン X の準備ができました」と「更新」ボタンが表示され、設定には点が付きます。インストールされたアプリは、`.gpg`、`.pgp`、`.sig`、`.asc` ファイルをシステムから（このアプリで開く）開いて、ファイルビューに取り込むこともできます。

## 制限事項

- 鍵サーバーや WKD はありません。ページにネットワークアクセスがないのは設計によるものです。鍵はファイルかテキストで交換してください。
- スマートカードやハードウェアトークンには対応していません。秘密の主鍵が別の場所にある鍵（GnuPG のスタブ）は読み込め、そのサブ鍵も使えますが、そのような鍵をここで変更することはできません。
- S/MIME や X.509 証明書には対応していません。OpenPGP のみです。
- 信頼は直接的です。自分の鍵による認証だけを見ます。GnuPG のオーナートラスト（他の人による認証を信頼すること）はモデル化していません。
- ファイルは丸ごとメモリーに読み込まれます。文書や写真なら問題ありませんが、数ギガバイトのファイルには向きません。
- 単独ファイル、PWA、拡張機能は、それぞれ独自のキーリングを持ちます（「[Chrome 拡張機能](#chrome-拡張機能)」を参照）。
- OpenPGP v6 の鍵は、GnuPG や Kleopatra ではまだ読めません。
